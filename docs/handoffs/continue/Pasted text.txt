## Per-report legacy inspection

For each LP-Rxx report, inspect:

### A. Navigation and page structure

Record exact menu hierarchy, page title, destination URL, sections, tabs, controls, filter defaults and all available options relevant to the report.

Preserve distinct legacy entries even when their pages look similar.

### B. Filtering and actual results

Inspect:

- Available date, month and year controls.
- Branch, customer, courier, vendor, mode, status and billing filters where applicable.
- Settled result tables and actual column order.
- Sorting, pagination and page-size behavior.
- Totals, subtotals, grouping and status buckets.
- Empty versus populated results.
- Relevant detail and drilldown links.

Prefer at least one populated, bounded read-only result where available.

If no populated result can safely be found, record this limitation rather than inventing records or formulas.

Distinguish visible labels from proven business semantics.

### C. Export and exported contents

**Export inspection is a primary acceptance requirement, not an optional afterthought.**

For every report exposing Export, Ekspor Excel, CSV, Download or Cetak:

1. Determine whether the action can be executed without business mutation.
2. Apply appropriate bounded filters before triggering it.
3. Execute the permitted export or print action.
4. Inspect the generated file/document using appropriate available tooling.
5. Record its real structure and relationship to the filtered UI result.

Inspect, as applicable:

- Actual file format, filename pattern and extension.
- Workbook sheets and sheet names.
- Header rows, column order and merged headers.
- Data types and display formats.
- Date, currency and decimal representation.
- Grouping, subtotals, totals and formulas.
- Row count and inclusion criteria.
- Differences between UI columns and export columns.
- Whether filters, branch scope and date boundaries carry through.
- Printable layout, page breaks and report headings.

Inspect sanitized structural information and safe aggregate evidence only. Keep downloaded files temporary and outside the repository; do not commit private exports.

If an export fails, distinguish application failure, browser/tool failure, permissions and unknown side effects.

A report cannot be marked export-parity verified without inspecting its actual output.

Do not repeatedly retry the same failed export without new evidence.
