# WA-01: branch WhatsApp gateway integration

Date: 2026-10-26. Owner: Dev 1. Peer review pending.

The stakeholder confirmed Baileys in a separately supplied project, with a
different WhatsApp number/session for each branch, and requested preparatory
setup in LMS. This supersedes the earlier deferral only for this foundation.
It does not approve automatic operational notifications or template storage.

This slice adds server-only gateway environment validation and an authenticated,
paginated branch inventory in the existing Office > Perusahaan > WA Notifikasi
panel. It uses the current `whatsapp_configuration:view` permission and existing
branch assignments; no new grant or HQ override is introduced. Active branches
and parents only. Company filtering and search must preserve branch scope.
Only administrators see configuration readiness, never the endpoint or key.
The panel initially reports that the gateway is not configured. With valid
configuration it reads live branch status; it never fabricates a connected number.

The stakeholder subsequently authorized choosing the API routes in LMS, with
the Baileys project following this contract. Status, QR, connect and logout now
use the authenticated gateway API described in [the v1 contract](WA-01-gateway-api.md).
QR and mutations require administrator access; normal readers retain their
branch-scoped view permission. This does not alter shared grants or HQ semantics.
There is no schema change, Baileys auth storage in LMS, public webhook or message
send. Existing company/customer notification preferences remain preferences,
not session ownership; do not reuse their IDs as session IDs.

## Setup

Copy the optional names from `.env.example` into the ignored local environment:

- `WHATSAPP_GATEWAY_URL`: the future Baileys service base URL. HTTPS is required
  except HTTP loopback in non-production. No URL credentials, query or fragment.
- `WHATSAPP_GATEWAY_API_KEY`: a server-only random secret of at least 32 printable
  ASCII characters, without whitespace (for example, `openssl rand -hex 32`).

Both values may stay empty until the project is available. Partial or malformed
configuration is reported as invalid without exposing submitted values. Filling
these settings enables live status checks and administrator connection controls;
pairing still requires an explicit connect and device scan. Do not use
`NEXT_PUBLIC_` variables. No local secrets are generated or overwritten here.

## Handoff to the Baileys project

The route/response contract is now chosen by LMS under the stakeholder's explicit
authorization. The Baileys project must implement [gateway API v1](WA-01-gateway-api.md).
Live interoperability remains pending until that project is supplied. Remaining
`BLOCKED: decision required, D-34` concerns operational message triggers/delivery
and any future schema change, not the implemented session transport. Handoff:

- How an authenticated gateway request binds to a stable LMS Branch Int ID,
  including environment/tenant namespace if more than one LMS uses the gateway.
- Service authentication; QR/pairing access, expiry and disclosure restrictions;
  who may connect/disconnect each branch. Existing view permission grants none
  of these mutations.
- Branch-isolated durable session storage and reconnect/logout behavior in the
  Baileys project. No auth keys or QR payloads in browser storage or application
  logs. Number/session mapping and any new schema require a separate reviewed
  migration; existing company preferences cannot be backfilled into branches
  without an explicit mapping.
- LMS uses explicit status/QR refresh, not callbacks. Any future webhook needs a
  separately reviewed signature and replay-protection contract.
- Operational message triggers, recipient ownership, idempotency, retries,
  consent and retention remain separate decisions with Dev 2/3 as applicable.

Tests cover environment validation, server permission/branch isolation, safe
DTOs, pagination and the preparation panel's loading/error/empty states. Shared
deployment, peer review and a live connection test remain pending.
