## Contract for Dev 2 and Dev 3

- Canonical grants and actor types: `src/features/identity/permissions.ts`.
  One group per user; supported actions are declared per resource.
  `system_admin:manage` is the current full-access override. A role's display name
  or an empty branch list never grants full access.
- Server context: `src/features/identity/server/context.ts`; authorization and
  actor loading: `src/features/identity/server/access.ts`. Authenticate and check
  action permission at every query/mutation entry point. Apply allowed branch
  IDs to the database query, not only the UI. Do not trust a submitted branch ID.
- Organization relationships currently follow Company -> Office -> Branch ->
  Agent. Drivers, couriers, marketing personnel and vehicles reference Branch.
  Geographic dictionaries remain flat. Vendor's existing branch text is not a
  branch FK and must not be treated as an authorization relationship.
- Global reference/organization mutations require administrator access in
  addition to their action grants. Branch-owned personnel/vehicle mutations
  require their action grant and branch scope. Vendor tax configuration is
  administrator-only. Read the canonical `permissionRestriction` helper.
- Identity/organization/reference writes re-check the initiating session and
  current actor around the policy transaction; audit and related writes are
  atomic. Keep these checks when adding consumers. Do not alter applied SQL.
- Domain master deletion is soft deletion, distinct from inactive status.
  Historical relationships remain protected. Existing uniqueness is retained;
  deleted identifiers are not silently reused.
- Provider menu labels live in `src/components/shell/navigation.ts`; link
  activation and existing resource mapping live in `accessible-navigation.ts`.
  Dev 2/3 must add their approved resource contracts and server checks when
  activating destinations. A visible menu is not permission enforcement.
- Error boundaries use sanitized `IdentityError`/validation responses and private
  uncached identity HTTP responses. Do not log credentials, identity numbers,
  contact fields or file content.

Approval: the stakeholder answered "Ya, tambahkan kolom dan migrasi Cabang" to
the explicit six-field proposal in this conversation.

Add nullable `String` fields to the existing Branch model:

| Prisma field | Database column | Form label |
| --- | --- | --- |
| postalCode | postal_code | Kode Pos |
| faxNumber | fax_number | No. Fax |
| email | email | Email |
| financeContactName | finance_contact_name | Finance |
| marketingContactName | marketing_contact_name | Marketing |
| taxId | tax_id | NPWP |

Existing rows remain NULL; no backfill, relationship, identifier, status or
financial value changes. No new indexes are justified for these non-filter
contact fields. Validation accepts omission from older clients; omitted fields
must not erase previously stored values. Email is validated when supplied.
Two address lines fit the existing address string as multiline text. Branch NPWP is returned only to administrators; branch-scoped readers receive null for that field.

Migration: `20261025000200_plt02_branch_reference_fields`. Add columns only; never
edit an applied migration. Forward fix by correcting values or a new reviewed
migration; a destructive down migration would lose newly entered contact data.
Independent developer review remains required before merge/shared deployment.

## Personnel import contract

- Download endpoints: `/logistics/division/template/driver`, `/courier`, and
  `/marketing_person` under that same template prefix. Each has its own columns.
- BIFF8 `.xls`, maximum 512 KiB and 500 records; validate and preview before save.
  Header row is row 3 of `Worksheet`. Driver includes SIM; other templates do not.
- Source provider ID and calculated branch-ID cells are ignored. New local IDs
  are generated. Resolve CABANG by an unambiguous allowed active local code/name.
  The guide sheet contains local branch references and fake examples only.
- KTP, phone and SIM input must be text to preserve leading zeros. Formula/error
  cells in input columns are rejected. Two address lines are joined with a newline.
- Exact duplicate rows/records are rejected; import never updates existing people.
  Any invalid row rejects the batch. Permission/session/branch checks are repeated
  during commit; personnel writes and audit events share one transaction.
- This bulk-create tool is not a provider-history migration or approval of D-02.

## Database and developer setup

There were 16 applied migrations before the six-field Branch refinement. The
working tree includes three PLT-01 migrations after the original 12 SCH-01
migrations, plus `20261025000100_plt03_vendor_services`. VendorService is additive,
with an Int vendor FK, lifecycle fields, status, vendor/status indexes and RESTRICT
referential actions; no existing vendor row or service is backfilled.

Personnel import, searchable assignment choices and development admin seeds
require no additional database schema. The Branch refinement is a separate
approved migration and must be applied by other developers after pulling it.

Use Node 24.15.0 and the committed npm lockfile. On a local development database:

```sh
npm ci
npx prisma migrate deploy
npx prisma generate
npm run db:seed
```

Before seeding administrators, configure **both** `DEV2_ADMIN_PASSWORD` and
`DEV3_ADMIN_PASSWORD` in the ignored `.env` (8-128 characters, distinct passwords).
The usernames are `dev2_admin` and `dev3_admin`, with `.invalid` development emails
and a dedicated `DEVELOPMENT_ADMINISTRATOR` group. No password is embedded in
source or `.env.example`. Without either password configured, admin seeding is
skipped; partial configuration is rejected.

Seed guard: non-production, localhost/127.0.0.1, database `logistik_web`, no URL
overrides. Fake fixtures and new admins are atomic. Reruns preserve existing
passwords, sessions, status and assignments; identity/group collisions fail
without takeover. Existing changed fake IDs also fail rather than being overwritten.
Never use these local seed accounts as production bootstrap.
